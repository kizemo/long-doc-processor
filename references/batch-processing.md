# 多文档顺序处理模式

一次处理多份**独立**文档（如 18 期课程转录），不可合并为单一文档。

## 适用条件

- 文档之间无章节归属关联；
- 每份文档最终独立交付（各自 HTML）；
- 单份规模过大或合并会破坏内容结构。

## 顺序策略

```text
前 3-5 份 → 暂停，与用户确认质量 → 继续剩余
```

每份按 Phase 0 → 1 → 3 单独处理（不进入 Phase 2 合并）。

## 文档索引

```markdown
| 序号 | 文档名 | 字符数 | 状态 | 输出 |
|------|--------|--------|------|------|
| 01 | Doc01.docx | 45230 | ✅ 已处理 | Doc01_final.html |
| 02 | Doc02.docx | 38100 | 🔄 处理中 | - |
| 03 | Doc03.docx | 52800 | ⬜ 待处理 | - |
```

状态：`✅ 已处理 / 🔄 处理中 / ⬜ 待处理 / ❌ 失败需重试`。

## 暂停与确认

完成前 3-5 份后暂停，向用户报告：

- 每份的字符数与 H1/H2/H3 数量；
- 信息量守恒与 5 类资产保留情况；
- verify_html 验收结果。

获得用户确认后继续剩余文档。

## 与 Phase 2 合并的区别

不进入 `phase-2-merge.md`；每份独立渲染；产物各自回写对应源目录。
