# 中文标点规范化 · v4.21

> **触发**:LLM 净化产物 / ASR 转录产物 / 讲师口述产物常出现半角英式标点 + 中文正文的混杂排版,
> 严重影响阅读体验。本 reference 描述 `NO-HALF-WIDTH-PUNCT-IN-CN-CONTEXT` 规约的完整方案。

## 触发模式(6 类典型反模式)

| # | 反模式 | 用户感知 | 文件位置 |
|---|--------|---------|---------|
| 1 | `今天,我们,明天;后天。` | 半角 `,;:。` 看起来像英文,中文阅读流被打断 | 2026-10-14 玺承 2026 双十一项目首版 cleaned.md 含 562 处 |
| 2 | `(8月28日) (M几级)` | 数字/字母外半角括号显得不够正式 |
| 3 | `"结束",没说什么` | 中文引号 + 半角逗号视觉割裂 |
| 4 | `**目标只能有一个**,不能既要又要` | markdown 加粗 + 半角逗号割裂阅读 |
| 5 | `...等待中...请稍候` | 三点省略号是英文习惯,中文应该用 `……` |
| 6 | `首先 -- 其次` | 半角 `--` 不像中文 em-dash,中文用 `——` |

## 解决方案

### 步骤 1:行级标点转换(`scripts/normalize_cn_punctuation.py`)

**12 类半角标点 → 中文全角**映射:

| 半角 | 全角 | Unicode | 触发模式 |
|------|--------|---------|---------|
| `,` | `，` | U+FF0C | 中文(or 上下文)之间 |
| `;` | `;` | U+FF1B | 中文之间 |
| `.` | `。` | U+3002 | 中文之间 |
| `:` | `：` | U+FF1A | 中文之间 + 行末(`基本盘:`) |
| `!` | `!` | U+FF01 | 中文之后 |
| `?` | `?` | U+FF1F | 中文之后 |
| `(` | `(` | U+FF08 | 中文之前(含数字/字母) |
| `)` | `)` | U+FF09 | 中文之后 |
| `"..."` | `"..."` | U+201C/D | 中文上下文,自动追踪开/合交替 |
| `'...'` | `'...'` | U+2018/9 | 中文上下文,自动追踪开/合交替 |
| `--` | `——` | U+2014×2 | 中文之间(可配 `--single-dash` 转 `–`) |
| `...` | `……` | U+2026×2 | 连续 3+ 点 |

### 步骤 2:三层防护机制

#### 防护 1:fenced code 围栏(` ``` ` 三行)

- 状态机跟踪 ``` 行切换 `in_fenced_code = not in_fenced_code`
- 在 fenced code 内完全跳过标点转换
- 例外:**代码内的中英标点**应保留半角(代码不翻译)

#### 防护 2:inline code + 链接 + 图片 + URL

- 用 `_INLINE_SKIP` 正则保护以下区段:
  - `` `xxx` `` (inline code)
  - `[text](url)` (链接)
  - `![alt](url)` (图片)
  - `http://...` / `https://...` (裸 URL)
- 这些区段保持原样不转换

#### 防护 3:行级 markdown 结构

- 跳过以 `|` 开头的表格行
- 跳过纯表格分隔行(`---`, `|---|---|`)
- 跳过以 `#` 开头的标题行(内部不应有半角,即使有也保留以便人工 review)

### 步骤 3:行级状态机 + 显式 Unicode 转义

**关键技术细节**:
- 全角字符**必须**用 `chr(0xFF0C)` 等显式 Unicode codepoint 获取,杜绝 Write 工具/编辑器自动转半角
- 双引号替换**必须先于**逗号替换(避免 ASCII `"` 阻断 lookbehind)
- 单引号同理

### 步骤 4:上下文类 `_CN_OR_MD`

```
_CN_OR_MD = [\u4e00-\u9fff\u3000-\u303f\uff00-\uffef\u2018\u2019\u201c\u201d\s*\-+\d%°]
```

包含:
- CJK 统一表意(`\u4e00-\u9fff`)
- CJK 符号和标点(`\u3000-\u303f`)
- 半角/全角形式(`\uff00-\uffef`)
- 中文引号(`\u2018/9 \u201c/d`)
- 空白(`\s*`)、连字符(`-+`)、数字(`\d`)、单位符(`%°`)

支持 `**text**,text`、`(8月28日)`、`10%-20%`、`(M几级)`、`"text",text` 等混合上下文。

**为什么必须放在 LLM 净化之后**:LLM 默认输出英文键盘标点(`;` `:` 等),即便经过 6 条硬规约强制规约,标点仍会回退到半角。**脚本是最终兜底**。

## 反模式

| 不要 | 因为 |
|------|------|
| 跳过 `normalize_cn_punctuation.py` | LLM 默认输出英文键盘标点是默认行为,脚本是兜底 |
| 用 sed/awk 批量替换标点 | 无法识别 fenced code + 链接 + URL 保护 |
| 把全角字符在源码里手写 | Write 工具可能自动转半角;必须用 `chr(0xFF0C)` |
| 不更新 `_CN_OR_MD` 类 | 中文引号 U+201C/D / 数字上下文 / 字母上下文都会阻断替换 |

## 已知边缘 case

- `(2026-09-02)` 半角日期括号 — 数字上下文 `_CN_OR_MD` 含 `\d` 已支持
- `(8 月 28 日）` 大括号混排 — 仅替换半角括号,全角括号保持
- `**text**,**text**` 多个加粗 — `_CN_OR_MD` 含 `*` 已支持
- `1.5 倍` 中数字小数点 — `_CN_OR_MD` 含 `\d`,会误替换(已知边界 case,可接受)
- `JavaScript (JS) 函数` 中英括号 — 半角 `(` 前是字母,JS) 为合法,JS) 为合法 — 替换为 JS(JS) (已知边界 case,可接受)
