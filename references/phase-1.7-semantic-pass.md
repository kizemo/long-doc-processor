# Phase 1.7 · LLM 语义优化（v4.17 新增）

> **位置**：Phase 1 净化 → Phase 1.5 通顺化 → Phase 1.7 语义优化 → Phase 2 合并 → Phase 3 渲染
>
> **v4.17 引入**（2026-09-29 边界 2026-06-03 项目复盘沉淀）

## 为什么需要这一步

v4.16 及之前的流水线用脚本 regex + LLM 净化两步，但**仍存在 4 类质量问题**：

1. **转录元数据残留**：H1 下的 blockquote（"课程来源 / 核心主题 / 文档生成"）是处理元数据，最终读者关心的是实质内容
2. **讲师/学员角色说明**："讲师总结"/"讲师指出"/"学员搜索时" 等角色前缀污染正文（违反 v4.10 NO-ROLE-PERSONA）
3. **标题缺少编号**：H2/H3/H4 没有 `1./1.1/1.1.1` 显式编号，影响搜索引擎/目录索引/章节引用
4. **ASR 错词 + 孤立词**：字典替换 + LLM 净化两步仍有漏网（LLM 是错词放大器，不是纠正器）

这些问题**纯 regex 解决不了**——必须由 LLM 做语义级判断。

## 输入 / 输出

| 阶段 | 文件 |
|---|---|
| 输入 | `<stem>_cleaned.md`（Phase 1.5 通顺化产物或直接 Phase 1 净化产物） |
| 输出 | `<stem>_cleaned.semantic.md`（LLM 优化产物，覆盖到 `<stem>_cleaned.md`） |
| 中间备份 | `<stem>_cleaned.before_semantic.md`（Phase 1.7 前备份） |

## 4 条硬规约（必须执行）

### 规约 1 · NO-DOC-META-BLOCKQUOTE

**删除范围**：
- H1 后 blockquote 元描述（`> 课程来源:...` / `> 核心主题:...` / `> 文档生成:...`）
- 任何 `<hr>` 水平线标记（H1 后第一个 `---` 分隔线）

**改写示范**：
```markdown
❌ 改写前:
# AI 助力主图点击率低 · 主图优化实战课

> 课程来源: 2026-06-03 电商培训直播课
> 核心主题: 淘宝/天猫运营 · 主图点击率优化
> 文档生成: long-doc-processor v4.16 流水线
>
> ---
>
> ## 1. 产品裂变底层逻辑

✅ 改写后:
# AI 助力主图点击率低 · 主图优化实战课

## 1. 产品裂变底层逻辑
```

### 规约 2 · NO-ROLE-PERSONA-EXTENDED

**改写示范**：

```markdown
❌ 讲师指出, 关键词、评价、问大家是挖掘隐性需求的三个核心渠道,三者缺一不可——关键词告诉你用户怎么搜,评价告诉你用户在意的点,问大家告诉你用户没明说的疑惑。

✅ 突出关键词、评价、问大家三个核心渠道，三者缺一不可——关键词告诉你用户怎么搜，评价告诉你用户在意的点，问大家告诉你用户没明说的疑惑。

---

❌ 讲师举例：黑色枕头。学员搜索时会输入"黑色枕头 男士"这类关键词，但隐性需求其实是耐脏。

✅ 黑色枕头是典型案例：用户搜索时输入"黑色枕头 男士"这类关键词，但隐性需求其实是耐脏。

---

❌ 学员在选品时，需要通过不同维度把隐性需求呈现出来。

✅ 选品时, 需要通过不同维度把隐性需求呈现出来。
```

**引号内例外**：`讲师说："xxxx"` 中的原话引用可保留（v4.10 规则延伸）。

### 规约 3 · HIERARCHICAL-NUMBERING

**强制编号规则**：
- H2：`## 1. xxx` / `## 2. xxx` ... 7 个（边界项目实测）
- H3：`### 1.1 xxx` / `### 1.2 xxx` ...
- H4：`#### 1.1.1 xxx` ...
- 总结章固定：
  - `## 7. 总结与行动建议`
  - `### 7.1 全文要点回顾`
  - `### 7.2 可执行行动清单`
  - `### 7.3 决策流程图`

**v4.24 补充（标题两级骨架 + 禁场次标签）**：

- **禁场次标签**：标题里不得出现「第一天上午 / 第二天下午 / 上午场 / 下半场」等 ASR 场次前缀，
  也不得残留旧编号。场次溯源只留在 `_handoff.md` / `_purge_stats.md`，不进正文标题。
  ⇒ 门禁 `NO-SESSION-LABEL-IN-HEADING`。
- **两级骨架预算**（按文档字符数比例化，**禁止绝对常量**）：

  | 层级 | 预算 | 说明 |
  |---|---|---|
  | H3 / 章 | ≤18 | 一章的知识点先归纳成 18 个以内的主题组 |
  | H3 / 全文 | `max(20, 字符数/3000)` | 20 万字符文档 ≈ 64 组 |
  | H4 / H3 | ≤18 | 一个主题组最多收 18 条 |
  | H4 / 全文 | `max(50, 字符数/400)` | 与 H3 预算同源，**不是**「禁用 H4」 |

- **要点**：H3 是**主题组**（可读的一句话主题，每组配 1-2 句导语），H4 是**原知识点**。
  原始材料一节课 400+ 个知识点时，正确做法是「归纳成 60 个左右主题组 → 知识点降为 H4」，
  **不是**把 400 个知识点全部压平成 400 个 H3。
- H3 数量超过预算时，先走 `phase-2.5-restructure.md` 的结构重排（`restructure_outline.py`），
  不要靠合并正文段落或删除知识点来凑数。

**改写示范**：
```markdown
❌ 改写前:
## 产品裂变底层逻辑
### 案例 1: 电钻
### 案例 2: 指甲剪
## 隐性需求挖掘
### 链接数计算公式

✅ 改写后:
## 1. 产品裂变底层逻辑
### 1.1 案例 1: 电钻
### 1.2 案例 2: 指甲剪
## 2. 隐性需求挖掘
### 2.1 链接数计算公式
```

### 规约 4 · NO-ORPHAN-WORDS

**修复范围**：
1. **ASR 同音错词**（即使字典替换过仍可能漏网）：
   - 内幕 → 类目 / 气氛需求 → 客户需求 / 推广课 → 推广课程
   - 解论 → 结论 / 加密货币 → 价格带 / 收获人数 → 收货人数
   - 加入段 → 价格段 / 高科赞 → 高客单 / 主视图 → 主图
   - 点率/点击力/点击了 → 点击率 / 摩特图 → 模特图
   - 演书服 → 演出服 / 桌教店 → 桌角店 / 打笔 → 打比(Doubao)
   - 主途 → 主图 / 燃品 → 产品 / 空投产 → 控投产
   - 汉堡国 → 汉堡包 / 空点机 → 控点机

2. **孤立词组**：
   - 段首："好/那么/对/那个/就是说/你看/我们看一下"
   - 段末："对吧/是吧/好吧/啊"

3. **破句**：标点不当造成的句意割裂
4. **重复词**：同一段内同一非专有名词出现 3+ 次

## 整体质量深化（规约外）

| 优化项 | 做法 |
|---|---|
| 连贯性 | 每章开头加 1-2 句承接上文的过渡 |
| 重复检测 | 同一观点多处出现 → 合并到首次处，后续用"参见 N.M 节"引用 |
| 数据一致性 | 同一指标全文必须一致 |
| 表格后总结 | 每个表格后加一句解释表格内容的话 |
| 列表后总结 | 每个列表后加一句总结列表的结论 |
| 标题长度 | H2 ≤15 字 / H3 ≤20 字 / H4 ≤24 字；标题内禁场次标签与旧编号 |

## 反模式

| 不要 | 因为 |
|---|---|
| 用 sed/awk 批量替换"讲师" | 破坏引号上下文 + 误伤名词（讲师证/讲师证 等） |
| 用 markdown 渲染器把 `<hr>` 当成段落 | 触发 verify_html.py 的 frontmatter artifact FAIL `17b` |
| 跳过 Phase 1.7 直接渲染 HTML | 4 条规约全靠 LLM 守 |
| 用纯 regex 给 H2/H3/H4 加编号 | 无法判断标题是否在引用块/代码块内 |
| LLM 净化时同步删除角色 + 元数据 | 净化阶段不分心，会丢失原意；交给 Phase 1.7 专攻 |

## v4.18 新增 2 条硬规约（2026-09-29 第二轮迭代）

### 规约 5 · NO-META-LECTURE-PREAMBLE-IN-SECTION

**触发模式**：章节正文内出现以下讲师铺垫/课间安排内容，应**提炼为一句话目标陈述或直接删除**：
- 课程安排类：`本次课程内容无法在短时间内讲完` / `本次仍把产品留下来再讲一遍` / `本次课会把底层逻辑明确讲清楚`
- 教学策略类：`本节的教学策略是：把每个模块的核心点先全部过一遍` / `这样至少能知道现在可以先做什么,再深入学习`
- 回顾上次类：`上一次讲了产品怎么去找` / `上一次讲了关键词流`
- 课堂安排类：`本次会现场写很多东西、写完会保留下来` / `不单独发资料,所有现场写的内容就是资料本身` / `今天能写出来、跟上节奏和思路的内容,才是有用的`
- 章节标题：`课程说明与本节目标` / `本节说明` / `课程概览` / `教学策略`

**改写示范**：

```markdown
❌ 改写前（1.1 课程说明与本节目标）:

### 1.1 课程说明与本节目标

本次课程内容无法在短时间内讲完。上一次讲了产品怎么去找(现场写过的内容,
真正能听懂非常有用),上一次讲了关键词流。本次仍把产品留下来再讲一遍,
加上怎么做裂变、怎么做图、怎么做分层。

本节的教学策略是:把每个模块的核心点先全部过一遍,过完再回过头讲产品流。
本次会现场写很多东西、写完会保留下来,不单独发资料。

很多运营者知道一些思路和方法,但不知道底层逻辑——本次课会把底层逻辑讲清楚。

> 本节核心结论:**做产品裂变,底层逻辑只有两条**:
> 1. **平台的展示规则**
> 2. **客户的需求**
>
> 两条同时满足,链接才能被目标客户看到。
>
> 后续所有案例(电钻、指甲剪、沙发)均围绕这两条逻辑展开。

✅ 改写后（1.1 本节核心结论）:

### 1.1 本节核心结论

> **做产品裂变,底层逻辑只有两条**:
> 1. **平台的展示规则** — 平台怎么把你的链接展示出来
> 2. **客户的需求** — 顾客有没有这个需求
>
> 两条同时满足,链接才能被目标客户看到;后续所有案例(电钻、指甲剪、沙发)
> 均围绕这两条逻辑展开,讲解如何把同一个产品"铺开"——不是简单地上很多链接,
> 而是按平台规则和客户需求去做有结构的矩阵。
```

**例外**：
- 第 1 章开篇若需要上下文承接，可保留 ≤2 句话作为过渡（如"承接上一节关于产品来源的讨论，本章展开平台展示规则与客户需求两条底层逻辑"）
- 引号内讲师原话可保留（与规约 2 NO-ROLE-PERSONA-EXTENDED 一致）

### 规约 6 · NO-SINGLE-LINE-BLOCKQUOTE-CALLOUT

**触发模式**：单行 `>` 引用块被作为视觉强调工具使用（LLM 净化产物），应**转 `**`加粗 inline**` 段落或合并到上下文**。

**反例**（LLM 倾向过度使用单行 blockquote 作 callout）：

```markdown
❌ 单行 blockquote（视觉噪声，应转 inline）：

> 这一个案例,确立后面所有产品的判断标准:**先问"客户需求是否存在差异",再决定要不要拆变体**。

> 一般只要某个类目下的流量占比**高于 1%**,就值得去做。

> 因此同一个关键词,**不同人群看到的展示结果是不同的**。

> 判定标准只有一条:**是否存在真实的客户需求差异**。

> 操作要点:**把评价和问大家里高频出现的客户需求,直接呈现在产品主图**。

> **链接数 = 平台规则机会 × 细分需求机会数量**

> **实操建议**:如果对公式不熟悉,可以从低往高出。

> 计划组的核心逻辑:每个计划只承担单一职能,单独服务重点宝贝。

✅ 改写后（inline 加粗段落）：

**这一个案例,确立后面所有产品的判断标准**:先问"客户需求是否存在差异",再决定要不要拆变体。

**关键指标**:一般只要某个类目下的流量占比**高于 1%**,就值得去做。

**关键推论**:因此同一个关键词,**不同人群看到的展示结果是不同的**。

**判定标准只有一条**:是否存在真实的客户需求差异。

**操作要点**:把评价和问大家里高频出现的客户需求,**直接呈现在产品主图**。

**链接数公式 = 平台规则机会 × 细分需求机会数量**

**实操建议**:如果对公式不熟悉,可以从低往高出。

**计划组的核心逻辑**:每个计划只承担单一职能,单独服务重点宝贝。
```

**例外（合法 blockquote）**：
- 多行 `>` 块（≥2 行）作为"核心结论 box / 核心逻辑 box"展示是合法的
- 表格内的 cell 引用（不在 markdown blockquote 语法范畴）
- 引用外部资料/讲义原文（带 `> 引自...` 标注）

**判断标准**：
- 单行 `>` → 转 inline
- 多行 `>`（连续 ≥2 行且 ≥2 个实质内容）→ 保留 blockquote box，但**禁止空 `>` 行作为段落分隔**（应用普通空行或合并段落）

## 已知陷阱

- LLM 优化时**不要让它"自由发挥"重新组织内容**——只做 6 规约 + 整体质量深化，不增加章节
- LLM 优化时**不要删除原文没有的总结章内容**——保持总结章由 Phase 2 merge 脚本生成
- LLM 优化时**不要把 H2 标题加粗**——markdown 标题靠 `#` 不是靠加粗
- LLM 优化时**不要新增单行 `>` blockquote**——视觉强调一律用 `**加粗 inline**`
- LLM 优化时**不要保留讲师铺垫段**——课程安排/教学策略/回顾上次类内容直接删掉,不必保留标题
