# 文档净化 Prompt 模板

> 用于 Phase 1 Step 2 子代理净化
>
> 版本：v1.1（2026-05-30 修复过度精简问题）

## 子代理净化指令

你是一个文档净化专家。请处理以下原始转录文本，输出净化后的 Markdown。

---

## 🔑 核心原则：信息量守恒

**信息密度可以提升（删除冗余表述、优化语句），但信息量不能减少。**

具体含义：
- ✅ 允许：重新组织语句、合并重复表述（同一观点反复解释3遍→合并为1遍）、多句合并为一句、按逻辑重组段落
- ❌ 禁止：合并后原来的任何一个独立观点/层次/信息单元消失
- 🎯 判断标准：原始文本有 N 个独立信息单元，输出必须仍有 N 个

**逐项核查清单（处理完成后必须逐项自检）：**
1. 所有概念定义/术语解释是否完整保留？
2. 所有实战案例的关键要素（店铺/方法/结果）是否保留？
3. 所有数据指标（数值、比例、时间）是否保留？
4. 所有逻辑推理链条（原因→推论→结论→建议）是否完整且不缺环节？
5. 所有表格/清单/步骤列表是否保留？

---

## 净化规则（4大类噪声清理）

### 1. 纪律语
清理：点名、签到、作业布置、考试通知、纪律维护等与内容无关的语句
清理："同学们"等无信息称呼

### 2. 引导语
清理：开场白（"准备开始今天的内容"）、纯过渡语（"那就是这样..."、"好，下面..."）
保留：能帮助理解内容结构的过渡语（判断标准：删除后会丢失上下文衔接）

### 3. 寒暄/闲聊
清理：与主题无关的个人经历、社会新闻讨论
例外：讲师用个人经验解释概念的可保留（此时承载了信息量）

### 4. 口语填充词+人称转换
清理：纯口头禅无信息量（"就是说"、"那个"、"然后"、"对不对"、"是吧"）
清理：重复的口语词、意义不明的叠词
人称转换：第一人称→"讲师"，"你们"→"学员"，"我们"→"讲师"或"大家"

---

## 资产保留要求（5类必须逐项保留）

1. **概念定义**：所有术语解释、概念界定、分类标准
2. **实战案例**：讲师分享的操作案例、店铺案例、数据案例（含完整要素：背景/做法/结果）
3. **数据指标**：所有数值数据、KPI指标、衡量标准、时间节点
4. **逻辑推理**：因果分析、策略推导、思路链条（原因→推论→结论→建议，每环节都不能缺）
5. **表格列表**：所有表格、清单、步骤列表

---

## 输出格式

### 标题规范
- L1（#）：章节标题
- L2（##）：节标题
- L3（###）：小节标题
- L4（####）：细分点标题
- 一级标题只在确实需要章节划分时使用

### 内容充实度要求
- 每个 H3 标题下至少2段正文
- 正文每段至少50字（不含标题行）
- 内容过短时合并同级标题

### 净化统计（**不写入文档**，仅在会话任务总结中报告）

所有净化统计、噪声清理计数、保留率数值、保留率异常说明等数据**不得写入最终输出文档**；仅在 Claude 会话的任务总结中向用户报告。

会话任务总结应包含：

- 4 大类噪声清理估算：[纪律语 X 处] [引导语 X 处] [寒暄 X 处] [口语填充词 X 处]
- 总中文字数：原始 [N] → 净化后 [N]，保留率：[X%]
- H1 数量：[N]，H2 数量：[N]，H3 数量：[N]
- 保留率异常说明（如适用）：[原因，如大段广告内容删除 / 大段重复讲师经历 / 长段与主题无关闲聊]

> 字符数计算方式：`len(re.findall(r'[\u4e00-\u9fff]', text))`——只统计 CJK 统一表意文字（U+4E00–U+9FFF），不含英文、数字、标点、空格、Markdown 标记。

**异常处理**：

- 保留率 < 55% 无合理原因 → 净化过度，必须重新处理；
- 保留率 55%–65% → 自行复核 5 类资产完整性后方可交付；
- 保留率 ≥ 65% → 正常交付。

> 对应验收：`references/qa-gates.md` Phase 2 Step 10 #12 "无 `## 统计` 区块残留" 已确保最终输出不包含此区块。

## Few-Shot 示例

### 示例1：单句净化（短文本）
**输入**：
"好的同学们我们现在开始上课了啊今天讲一下标签的问题那个就是说呢标签这个东西其实就是人群标签你们做淘宝的都知道的哈2026年标签权重从30%提升到45%了对不对"

**输出**：
标签即人群标签。2026年标签权重从30%提升到45%，是搜索算法近年最大的一次权重调整。

### 示例2：段落净化（长文本 · 🔑 关键示范）
**输入**：
"好，关于直通车标准计划这边呢，讲师跟大家说一下啊。就是说标准计划它的核心是什么呢？核心就是关键词出价。那很多学员在做的时候有一个误区啊，就是说觉得出价越高排名就越好。这个观点其实是错误的，至少不完全对。为什么呢？因为淘宝现在考核的不仅仅是出价这一个指标。淘宝会看你的人群标签匹配度，还有你的点击反馈数据，如果人群不匹配的话，你出价再高也是排不上去的。所以讲师给学员们的建议是什么呢？第一个，先做好人群测试。再一个呢，不要一上来就高出价，先从行业均值开始逐步往上调。"

**✅ 正确输出**：
标准计划的核心是关键词出价。许多学员存在一个误区——认为出价越高排名就越好。这个观点是错误的，因为淘宝现在不仅考核出价指标，还会考量人群标签匹配度和点击反馈数据。如果人群不匹配，出价再高也无法获得好排名。

因此，讲师建议：
1. 先做好人群测试
2. 不要一上来就高出价，从行业均值开始逐步上调

**❌ 错误输出（过度精简）**：
标准计划核心是关键词出价，需注意人群匹配度。

> 错误原因：丢失了「误区说明」「为什么不完全对」「具体建议步骤」三个独立信息单元。

## 处理要求
- 目标保留率：65%-75%（纯中文字数计算）
- 禁止编造内容，不添加原文没有的信息
- 禁止添加"本章小结"、"核心要点"等非原文段落
- 处理完成后必须逐项核查5类资产的完整性

## 11. v4.17 新增 4 条硬规约（LLM 语义分析强制执行）

> **强制要求**：以下 4 条必须由 **LLM 调用处理**，不允许用纯 regex 脚本批量替换。
> 理由：regex 无法判断引号内的"讲师总结"是否在例外范围内、无法识别跨段连贯性问题、无法修复 ASR 同音错词的上下文依赖。

### 11.1 NO-DOC-META-BLOCKQUOTE（H1 后元数据清理）

**删除范围**：
- H1 标题后的所有 blockquote 元描述（`>` 块）
- 内容含"课程来源 / 核心主题 / 文档生成 / 流水线 / 转录稿"等转录/处理流水信息
- 任何 `<hr>` 水平线标记（H1 后第一个 `---` 分隔线）

**保留**：H1 标题本身（即使它包含"AI 助力主图点击率低"这种课程名信息）

### 11.2 NO-ROLE-PERSONA-EXTENDED（讲师/学员主语删除）

**全文扫描并改写**所有"讲师/学员"作主语的开头：

| 改写前（删除） | 改写后（直接陈述） |
|---|---|
| 讲师指出 / 讲师总结 / 讲师强调 | 直接陈述观点（隐含主讲人） |
| 讲师举例 / 讲师解释 / 讲师说明 | 给出案例 / 解释 / 说明 |
| 讲师提醒 / 讲师建议 / 讲师补充 | 直接给出提醒 / 建议 / 补充 |
| 学员搜索时 / 学员常见的错误想法 | 用户搜索时 / 常见错误想法 |
| 学员要根据 / 学员在选品时 | 应根据 / 选品时 |
| 讲师同时提醒 / 讲师特别说明 | 同时提醒 / 特别说明 |
| 案例 X: 讲师点评 | 案例 X: |
| 讲师认为 / 讲师说 | 删除（结论直接表达） |

**例外**：直接引用讲师原话（带引号 `"xxx"` 或 `'xxx'`）**可保留** "讲师说：'xxx'"。这是 v4.10 NO-ROLE-PERSONA 的延伸规则，原话引用场景允许角色明示。

### 11.3 HIERARCHICAL-NUMBERING（标题强制编号）

**强制规则**：
- 所有 H2/H3/H4 标题必须显式带阿拉伯数字编号
- H2 编号：`## 1. 主题` / `## 2. 主题` ... 连续不断号
- H3 编号：`### 1.1 子主题` / `### 1.2 子主题` ...
- H4 编号：`#### 1.1.1 细分` ...
- 总结章 H2 编号：与最后 H2 + 1（v4.9.1 必做）
  - `## 7. 总结与行动建议`
  - `### 7.1 全文要点回顾`
  - `### 7.2 可执行行动清单`
  - `### 7.3 决策流程图`

**检测脚本**：`scripts/renumber_headings.py` 可校验，但最终由 LLM 写入。

### 11.4 NO-ORPHAN-WORDS（孤立无语义内容修复）

**修复范围**：

1. **ASR 同音错词残留**（即使字典替换过仍可能漏网）：
   ```
   内幕 → 类目    气氛需求 → 客户需求    推广课 → 推广课程
   解论 → 结论    加密货币 → 价格带    收获人数 → 收货人数
   加入段 → 价格段   高科赞 → 高客单   主视图 → 主图
   点率/点击力/点击了 → 点击率   摩特图 → 模特图
   演书服 → 演出服   桌教店 → 桌角店   打笔 → 打比(Doubao)
   主途 → 主图   燃品 → 产品   空投产 → 控投产
   汉堡国 → 汉堡包   空点机 → 控点机
   ```
2. **孤立词组**（句首/段末无意义字）：
   - 段首孤立"好/那么/对/那个/就是说/你看/我们看一下"
   - 段末孤立"对吧/是吧/好吧/啊"
3. **破句修复**：标点不当造成的句意割裂
4. **重复词**：同一段内同一非专有名词出现 3+ 次

### 11.5 强制 LLM 调用（不允脚本）

4 条规约的检查方式必须是 **LLM 主对话 / Subagent 调用**，理由：

| 场景 | regex 失败点 | LLM 优势 |
|---|---|---|
| 讲师总结（在引号内 vs 不在） | 无法判断引号上下文 | 语义识别引号边界 |
| "讲师"是名词还是角色（讲师证/讲师证 vs 讲师总结） | regex 替换会误伤 | 词性 + 句法分析 |
| 标题编号跳号 / 重复编号 | regex 检测不到结构 | 全局连贯性推理 |
| 跨段错别字（如"主图"出现 8 次但其中 2 次被改成了"主途"） | regex 需要预先知道错词 | LLM 直接读出"主途"是错的 |

**自动化阶段**：`scripts/renumber_headings.py --preview` 可生成冲突报告，但写入必须 LLM 调 `Edit` 工具或 Subagent 完成。

### 11.6 整体质量深化（v4.17 在规约外补强）

| 优化项 | 做法 |
|---|---|
| 连贯性 | 每章开头加 1-2 句承接上文的过渡 |
| 重复检测 | 同一观点多处出现 → 合并到首次处，后续用"参见 N.M 节"引用 |
| 数据一致性 | 同一指标全文必须一致（如"100 收货人数首页"不能在别处变成"100 收货人数上第 1 页"） |
| 表格后总结 | 每个表格后加一句解释表格内容的话 |
| 列表后总结 | 每个列表后加一句总结列表的结论 |
| 标题长度 | H2 ≤15 字 / H3 ≤20 字，超过的应拆分或精简 |

### 11.7 反模式（v4.17 警告）

- **禁止**用 `sed -i 's/讲师/ /g'` 类脚本批量替换（破坏引号上下文 + 误伤名词）
- **禁止**用 markdown 渲染器把 `<hr>` 标记当成段落（会触发 verify_html.py 的 frontmatter artifact FAIL `17b`）
- **禁止**跳过 Phase 1.7 LLM Semantic Pass 直接渲染 HTML（4 条规约全靠 LLM 守）
- **禁止**用纯 regex 给 H2/H3/H4 加编号（无法判断标题是否在引用块/代码块内）
